> 2025年12月到2026年9月，有人用 Common Crawl 扫出了15.9万个用 Lovable 生成的网站。其中24,664个网站，加载页面的瞬间就开始从数据库往浏览器里吐记录——不需要登录，不需要任何凭证。研究者又补了一发只读请求，在7,403个网站、10,560张表里拿到了带邮箱的数据，占被细查网站的三成。

这不是一起数据泄露事故。这是一场批量生产出来的裸奔，只是规模统计第一次摆到了台面上。

## 三万个连着同一个数据库的项目，三分之二不设防

先把数字摆清楚。安全团队 Crissyfield 和《商报》联合做的这项调查，方法论很朴素：不搞什么高级攻击，就是拿 Common Crawl 的爬虫快照去识别 Lovable 生成的站点，然后像普通访客一样打开网页、看浏览器控制台里流过什么。结果分三层：

第一层，15.9万个项目里有34,545个接了 Supabase 做后端。第二层，其中24,664个网站——接近三分之二——在页面加载时就有数据库记录直接返回前端，登录这一步整个被跳过了。第三层，在追加只读请求做细查的样本里，30%的网站能取到含邮箱的记录。

具体到个案，画风就从统计变成了惊悚：某德国生活论坛，八万余份用户资料外加二十多万条聊天消息，姓名、邮箱、生日、性别一应俱全；某服务商，一千多条身份证件记录，护照号、有效期、国籍列得整整齐齐；还有一家，二十八万封已发出的客户邮件。票务、餐饮订单、合同、发票、私人相册、内部 WhatsApp 通信——你能在一个小生意里想到的所有数据类型，都在公网上开着门。

当然要说句公道话：研究者自己都强调，30%这个数不能直接当"泄露率"读，抽样有偏差，能被细查到的网站本来就是暴露概率更高的那一批。但这个免责声明救不了任何人，因为真正的攻击者不写免责声明，他们只写一行 fetch 请求。

问题出在哪？Supabase 这类后端即服务的安全模型，依赖开发者主动配置行级安全策略（RLS）。策略没开，数据库默认就像一张摊在桌上的表。职业工程师会踩过这个坑——但起码知道有这么个坑。Lovable 的典型用户是设计师、运营、想给自己小生意做个订餐页的店主，他们连"RLS"三个字母是什么意思都不知道，AI 说能跑，他们就说谢谢。

## 漏洞太多，连"负责任披露"都谈不动了

无独有偶，同一天 Google Project Zero 发布了新版披露政策，标题起得很直白——《Policy and Disclosure: 2026 Edition》。改动的原因，Natalie Silvanovich 写得毫不含糊：过去一年只找得出几个漏洞的目标，现在 LLM 上手，一周就能找出好几个；旧政策里那些依赖与厂商一对一协商的部分——漏洞修没修、要不要给宽限期——"迅速变得无法管理"。

把这两件事放在一起看，会发现它们其实是同一个现象的正反面。LLM 同时降低了两个方向的成本：让不会写代码的人一天生成一个应用，也让找不到漏洞的人一周挖出一堆洞。产出端的量级翻了几十倍，审计端、修复端、协商端的流程还是按老量级设计的——于是 Lovable 那边是三成网站裸奔没人管，Project Zero 这边是披露队列堵到谈不动，只能改规则。

更有意思的是 Project Zero 的姿态变化。这个团队过去十年是"负责任披露"的旗手：报告、协商、等待、再公开，一套流程体面而克制。现在他们公开承认这套体面撑不住了。当漏洞的发现速度超过厂商的响应速度，"协商"就不再是安全机制，而变成了拖慢攻击者的唯一理由都存疑的仪式。这不是 Project Zero 变激进，是数学变了。

## 易用性是一种债务转移，而债务不会消失

我真正想说的是：vibe coding 没有消灭安全工作，它只是把安全工作从"开发者的事"转移成了"所有路过的人的风险"。

传统软件工程里，安全和易用是一对要权衡的冤家，但至少账是记在明处的：一个团队写代码，一个团队做审计，欠了债自己还。vibe coding 的模式是——平台把"能跑起来"包装成产品，把权限配置这种真正要命的决定，藏进默认值和用户根本看不见的选项里。用户以为自己在买一个订餐页面，实际上连自己数据库的访问控制一起买走了，而收银台从没提示过这一项。

还有一层更隐蔽的账：S&P Global 的数据显示约42%的 AI 项目最终被母公司放弃。Character.ai 成立五年申请破产，一批批 AI 应用的独立入口被关停合并。放弃一个项目的门槛越低，被遗弃在公网上继续裸奔的数据就越多——项目死了，数据没死。三成裸奔网站里，有多少是主人早就不记得密码的"僵尸应用"？没人统计过，但按42%的放弃率倒推，这个数字不会小。

所以该怪谁？骂用户不懂 RLS 没有意义，就像骂麦当劳顾客不懂食品加工。生成式开发平台真正的产品责任，是把"你的数据库现在对全世界开放"做成一个阻塞性的警告，而不是一行埋在文档里的 FAQ。易用性工程做到今天，连低电量提醒都能弹得人心烦，唯独几万人的邮箱和护照号躺在一行公开的 fetch 请求后面，一个弹窗都没有。这不是技术做不到，是做这件事不产生留存，不产生营收——在增长指标面前，安全默认值是永远排在下个迭代的事。

## 结语

日报今天的主线是英伟达的权力交接，但我觉得 Lovable 这份报告才是更有长期意义的信号：它第一次给出了 vibe coding 安全债的定量读数——不是"存在风险"这种废话，而是三分之二、三成、二十八万封邮件这样具体到可以追责的数字。

AI 把写代码的门槛从专业降到了大众，这个成就无可争议。但每一个被降掉的门槛，背后都有一道曾经靠专业门槛守着的防线。防线拆了，墙没砌，三万个项目的数据库就那么开着门等风来。下一个爆出来的可能不是 Lovable——任何把"生成"做得比"审计"容易的平台，账单都已经在路上了。区别只是：Lovable 的先寄到了。
